# M4.29 Dolby / HDR 设备能力检测验收报告

基线：`e1e8d6f44586cc2d8a7af5f1fc1b9777f0eaa0a2`。分支：`feat/herrin-m4-29-dolby-hdr-capabilities-20261029`。
目标设备：TCL T7L Ultra，使用电视自带扬声器。本报告没有该电视的实机测试结论。

## 已实现

- `DeviceMediaCapabilities.kt`：无 Android 依赖的能力快照、三态查询结果、HDR 类型和 Dolby 音频分类。显示能力与解码器能力分别记录，不根据电视型号硬编码。
- `DeviceMediaCapabilitiesAndroid.kt`：读取指定显示设备的 HDR 能力（Dolby Vision / HDR10 / HDR10+ / HLG），枚举 HEVC、Dolby Vision、AC-3、E-AC-3、E-AC3-JOC 解码器及 profile/level。API 29 以上使用系统 `isHardwareAccelerated`，较低版本保留 UNKNOWN，不凭名字猜硬件解码。
- 音频采集分别记录解码器支持、48 kHz / 5.1 的 `AudioTrack.isDirectPlaybackSupported` 声明、可用输出设备及其 encoding，识别内置扬声器。直出不支持不等于 Media3 无法解码再输出 PCM；本模块不强制直出。
- `MediaQuality.kt`：现有画质标签与 Apple TV 风格 UI 保持不变；增加 `SELECTED_TRACK` 证据阶段、普通 Dolby Audio / Atmos 编码分类，以及明确的 `UNCONFIRMED` 输出状态。
- 读取厂商能力 API 失败时保守返回 UNKNOWN，不阻止启动或改变播放设置。无网络查询，无 Cookie/Token/播放 URL 日志。

## 三类证据的边界

1. **设备宣称支持**：Android Display、MediaCodec、AudioTrack 的能力声明。HDR10+ 的数值类型必须由 Display 明确报告，不能由 PQ、HDR10 或电视营销名称推断。
2. **已选中媒体轨道**：Media3 选中轨道的 MIME / 分辨率 / colorTransfer。PQ 仅显示 `HDR (PQ)`；JOC 可识别为 Atmos 音轨。音轨存在不代表解码或实际输出成功。
3. **实际输出成功**：本阶段不能从通用 Android API 可靠证明 TCL 内置扬声器已输出 Atmos，或屏幕已进入 Dolby Vision / HDR10+ 模式；因此保持 `UNCONFIRMED`。没有虚构“已输出”状态。可用扬声器清单并非活动播放路由。

快照应在显示器或音频路由变化后重新采集。解码器 profile/level 是设备声明，不是对任意 4K 码率、帧率、DV profile 或受保护内容的播放承诺。未实现 TrueHD Atmos 的 bitstream 解析；只有明确 E-AC3-JOC MIME 可归类为 Atmos 音轨。

## 自动验证

- `python3 scripts/check_static.py`：PASS。
- JVM 回归覆盖四类 HDR 映射、未知/不支持区别、软件/硬件解码器区别、显示与解码独立、Dolby Audio 与 JOC 区别、PQ 不继承 HDR10+、Atmos 与内置扬声器不构成输出确认。
- 新增 Android instrumentation：能力结果与实际平台 Display / MediaCodecList 一致，缺失显示设备返回 UNKNOWN；不假定模拟器具有 Dolby/TCL 硬件。
- 隔离编译：使用本地 Gradle 8.9 的 Kotlin 1.9.23 编译器和 SDK 35 的 `android.jar` 编译三个生产文件；JUnitCore 实际执行新增的 9 个 JVM 测试全部 PASS。该隔离检查不替代完整 AGP 构建。
- 首次完整 Gradle 命令 `:app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest --no-daemon --max-workers=2` 在 `checkDebugAarMetadata` 阶段失败：基线的 `com.github.thegrizzlylabs:sardine-android:0.9` 从 jitpack.io 下载收到 HTTP 403。依赖由主代理统一处理，修复后必须重跑完整检查。
- 本地没有 `/dev/kvm`，未启动 Android TV 模拟器；Android instrumentation 编译不等于执行，更不等于 TCL 真机验收。

## 范围和未实现

没有更换 Media3，没有强制软件 HDR 转 SDR，没有更改播放器 UI、遥控器焦点/返回、剧集/线路/播放 ID、Cookie 会话策略，也没有加入受保护二进制。播放器继续沿用既有 Media3 硬件选择逻辑；本模块仅提供检测基础。独立采集器尚未增加设备路由监听或 UI 展示，后续接入时需在生命周期内刷新快照。

## TCL 实机验收（待后续执行，不要求当前用户人工测试）

- 在电视内置扬声器路由下采集能力，切换 HDMI / 蓝牙后刷新，确认不会沿用旧能力或将可用设备当当前路由。
- 使用获授权 SDR、HDR10、HDR10+、HLG 与不同 Dolby Vision profile 测试素材，分别记录显示声明、选中轨道、实际电视画质提示与解码器；PQ 素材不能标成 HDR10+。
- 使用 AC-3、E-AC-3、E-AC3-JOC 合法素材，记录音轨与电视实际声音模式；没有额外证据不得展示“已输出 Atmos”。
- 测试不支持 profile、路由变化、后台/返回、连续换线/换集；确认失败仍可回退且未丢失播放身份。
