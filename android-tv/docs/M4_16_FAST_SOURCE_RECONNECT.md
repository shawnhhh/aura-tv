# HERRIN M4.16 — 最近可用影视站点快速重连

## 发现的问题

TVBox 单仓经常包含许多不可用、需要登录或暂时超时的 CMS/Spider 站点。HERRIN 之前每次启动都先逐个尝试最多 8 个 CMS 接口（每个约 9 秒连接/读取超时），再尝试最多 12 个 Java Spider 站点（每个最长 30 秒）。即使用户此前已成功打开后面的站点，下次仍可能在前面白等。

## 本次修改

1. 成功读取影片列表后，记录用户当前已应用的 TVBox 根地址和成功站点身份。用户从站点选择界面或高级预览手动选择成功时也更新这条记录。仅记录可用站点身份，不记录电影或播放凭据。
2. 下次相同根地址再次加载时，先尝试上次成功站点。若失败，恢复原有策略：最多 8 个 CMS 站点，再按影视优先、云盘/片单/预告/音乐靠后排序的最多 12 个 Spider 候选。候选去重，失效的历史站点不阻止回退。
3. Spider 身份包含实际使用的 **JAR URL 与 MD5 规范**；当配置更换 JAR，旧偏好自动失效。此偏好只是排序提示，**绝不替代**已有的「用户本次明确应用，或根地址+JAR 校验匹配」的执行许可。
4. 详情/画质/字幕与 D-pad 动效无变更，原有 UI 样式和无导航底部横条的决定保持不变。

## 自动化验证

- JVM 测试：后部已成功的 Spider/CMS 优先、失败时原顺序回退、变更 JAR 校验不能复用偏好或插件自动执行授权、去重。
- 需以本提交 GitHub Actions Android Debug、Lint 和 Android TV 模拟器运行结果作为 CI 验收；仅有静态测试不代表 TCL 真机性能已改善。

## 边界

- 本次针对**重复启动/重新应用后的站点探测等待**，不是 Android 系统打开应用到原生启动画面之前的启动延时。若首次导入没有历史成功站点，仍需搜索候选。网络不通、JAR 失败以及原生插件阻塞仍可能拖慢首次扫描。
- 受保护 ARM JNI Spider、真实饭太硬图片/视频与 TCL T7L Ultra 的端到端播放尚须实机验收；Draft PR 保持不合并。
