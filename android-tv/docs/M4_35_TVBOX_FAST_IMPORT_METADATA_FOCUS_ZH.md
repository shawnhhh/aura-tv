# HERRIN M4.35：TVBox 式快速导入、遥控器选线、TMDB 刮削入口

## TCL T7L Ultra 用户真机问题（2026-10-29）

- TVBox 配置导入在设置页显示“正在尝试 Spider 1/12”，启动很慢；
- 误以为“只导入 1/12 个站点”；
- 部分云盘播放提示“需要使用浏览器 App 扫码登录”，却没有二维码弹窗；
- 第三方弹幕服务启动失败；
- 遥控器方向键下不能从选集进入线路；
- 海报仍采用视频来源自带图片，而非网易爆米花式统一识别、展示和刮削。

## 本次完成

### 1. 配置导入不再启动 12 个 Spider
- 根配置/多仓 JSON 读取后立即保存所有站点清单（单仓最多 300 个 site），直接在“选择影视点”列出。
- 不再在导入过程中串行扫描 8 个 CMS + 12 个 Spider；不再自动顺序下载最多 5 个多仓子配置。
- 用户主动选择影视点时，才访问该站点和运行其插件；如之前同仓同版本已手动选过某个成功站点，启动时最多恢复它 **1** 个。
- 明确区别“导入配置成功”与“读取站点的影片成功”，并把实际 site 数展示在设置/选点页。
- `M435FastTvBoxImportTest` 验证未选过站点时无任何自动探测，以及只有精确匹配的上次站点恢复一次，改 JAR/改 site 不能继承之前选择。

### 2. 详情页遥控器 D-pad 下键切换线路
- 移动“播放线路”横排至选集正下方、剧情简介之前，避免下键进入无关的其它详情区域。
- 为播放线路首个按钮设置显式 `FocusRequester`，选集按钮下键优先进入线路列表；焦点目标尚未附着时交回 Compose 默认焦点搜索。
- 保留线路选择实际源 ID 及 `screen=player` 原有播放行为，不复制或猜测播放地址。
- 现有剧集/多季独立 SeasonBrowser 的线路展示保持原样。

### 3. 智能海报墙（TMDB）
- 现有匹配严格取自 TMDB，播放源仍由 TVBox 导入的当前站点提供，防止刮削改变播放权限和集数。
- TMDB Token 从非响应式的读取改为 Compose 状态；普通“设置·内容来源”直接提供密码输入、保存并开始刮削、重新刮削。
- 保存后立即启动后台匹配，无需重新打开页面；重新刮削时恢复源内展示字段，再用新匹配结果替换。展示已处理/匹配的数量。
- 单轮匹配从前 80 条扩大到前 240 条，最多 3 个并行请求，依托已有磁盘缓存和 TMDB 匹配安全约束。
- 没有 TMDB Token 时明确解释“仅显示影视源海报”。不内置、泄露或臆造第三方 API 密钥。严格匹配失败时保留原始图片，不拿错误影视海报替换。
- 此阶段使用官方 TMDB API；不是复制网易爆米花的私有刮削服务，也尚未实现全站无凭据自动刮削、人工挑选错误匹配等更高级能力。

### 4. 关于云盘扫码与弹幕
- 用户看到的“需要浏览器扫码登录”一般来自第三方 CatVod/网盘插件，需要 TVBox 所提供的 Activity、扫码网页、Token 回写、或回调接口。
- HERRIN 的插件运行于独立 :spider Service；当前没有把 `com.github.catvod.Runtime.setActivity`、`Runtime.setDialog` 跨进程映射到 Compose 主 Activity，所以不会自动弹出同款二维码。**本 PR 没有把该能力伪装为已经支持**。
- “弹幕服务启动失败”是另一条可选扩展服务问题，不应和 Media3 原生音视频解码、Spider 播放地址生成混淆；本 PR 不会无中生有启动未实现的弹幕服务或绕过用户授权。
- 选择站点页增加可见的兼容边界提示。扫码登录和弹幕服务应设计为后续独立、可控权限的 Activity/IPC 子系统，并在有权使用的账号与测试环境中验收。

## 必须通过的验收
- 统一 Android Debug 的静态检查、JVM 测试、Lint、Debug APK；
- Android TV 模拟器所有 instrumentation，保留已有 Spider MP4/HLS 真实画面验证与遥控器基础测试；
- 用 TCL T7L Ultra 检查导入阶段无“1/12”轮询、点选站点时才加载、下键进入线路、Token 保存可见进度与图片展示变化；
- QR 和弹幕尚未实现，因此不能作为已通过功能；要单独设计和复测；
- 外部实际影视资源与 Dolby/HDR 硬件输出仍未由模拟器证实。

## 变更约束

所有改动保持 Draft PR，基于 M4.34 #41 最新成功提交，不更新已有 PR 或主分支，不自动合并、不收集私人登录凭据、不实现 DRM 规避。
