# HERRIN M4.44 — 当前影片背景优先和取消过期海报请求

## 基线和风险

上游 M4.43 Draft #51 包含 72 次逐键 + 20 次无逐键 idle 的遥控器回归、实际按键到焦点回调/合成帧的统计，并已经减少了竖版 Hero 全屏 GPU 模糊。M4.44 继续沿真实诊断结果改进图片加载调度。

原实现所有贴图和大 Hero 下载共用一个 **4 permit** 的 Java Semaphore。首页几十张图同时加载时，四个 permit 可以被非当前焦点的缩略海报占满；此时用户切到另一部电影，即使已显示正确的焦点和文字，仍需等非关键下载释放 permit 才能加载大背景。另一问题是 `LaunchedEffect` 的任务在焦点离开后取消，但 Java Semaphore 阻塞等待不会自动感知协程取消。

## 修改

1. `PosterRequestBudget` 划分共享网络并发预算为 **3 张普通海报 + 1 张当前影片 Hero**。总并发仍是四，Hero 不排队等待无关普通海报全部释放；不启动额外线程池，不暴增网络连接。
2. 下载 permit 采用 35ms 周期的 `tryAcquire`。对 Compose 实际发起请求的 `Job.isActive` 做检查：被快速扫过、已取消的任务不再等旧 permit，也不会无意义地获取新连接。
3. 在远程连接打开之前、收到图片流逐段读取之间、解码前以及解码后继续检查任务是否失效；取消后的已解码、尚未缓存位图立即回收，防止误将退出屏幕的图片写入磁盘缓存。
4. 仍保留 URL 许可、HTTP 同意、图片 MIME/大小限制、私有缓存和完整的已有图片/视频功能，不使用额外插件或第三方密钥。
5. 新增 JVM 并发控制回归：普通海报占满不阻塞 Hero、等待时取消可退出、不泄漏 permit、取消后恰好取得 permit 的竞态不会泄漏。
6. 新增 Android HTTPS MockWebServer 端到端测试：请求启动前取消时服务器请求数为零。

## 本轮有意识的边界

- 如果一个 HTTP 连接已经进入阻塞式 `InputStream.read()`，外部协程取消并不能即时抢占该系统调用；本轮在下一次读循环中止并保留原有读取超时（最多 8 秒）。本轮不是完整的协程原生图片管线。
- Hero 自身限并发 1。如果多次急速换片，旧 Hero 阻塞读可能暂时占着唯一 permit；后续如实测发现此问题，需要针对 HTTP 连接主动断开或迁移到合作式 suspend API，而不是假称已有完全抢占能力。
- JVM 单测证明并发预算与取消语义，Android TV 回归证明整体功能；性能提升需采用 M4.43 同型号模拟器实测以及 TCL 真机对比才能确认。
- 所有 PR 保持 Draft，不能合并 main/master。
- 当前阶段仍不涉及音乐、短视频或任意 DRM 绕过。
