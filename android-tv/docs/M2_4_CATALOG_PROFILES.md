# HERRIN M2.4 — 本地多目录源管理

本阶段继续沿用独立 Kotlin/Compose TV 外壳和 Media3 播放器。它不是 FongMi 解析器，也不内置爬虫、影视源或任何需要授权的第三方内容。

## 用户能力

- 在电视「设置」中为已授权的 **HTTPS JSON 目录**填写可选名称和 URL，保存并启用。最多 10 个。
- 同 URL 再次保存只切换到原有条目，不重复添加。
- 可在已保存的目录之间切换，也可随时切回「离线演示」。
- 已存在的单个 `catalog_url` 在首次使用新版本时迁移为「原有目录」，不丢弃旧地址。
- 视频测试流设置保持独立；已有「保存媒体配置」入口保持兼容。
- 切换时立即移除屏幕上上一目录的影片数据，防止网络加载期间错误显示旧来源内容；网络失败仍采用原有离线占位和按 URL 独立的缓存策略。
- 收藏按授权目录的规范化 URL 分区；离线演示保留原来的 `favorites` 数据。旧版混用的全局收藏会在迁移时保守复制一份到「原有目录」（原始来源不可完全恢复），不删除原集合。原有续播机制继续按目录、影片、集数和线路隔离。

## 数据约束

- `SharedPreferences("herrin")` 的 `catalog_profiles_v1` 存储受限 JSON 数组，每项仅包含随机 ID、名称、规范化 HTTPS URL；活动目录 ID 存于 `active_catalog_profile`。
- 为兼容既有 M2 目录加载器，活动 URL 同步写入 `catalog_url`；选用离线演示时设为空串。
- 名称最长 32 个字符，不允许控制字符；目录 URL 经已有 `AuthorizedUrls.https` 验证。不存 API 密钥或抓取器配置。
- 收藏的存储键使用目录 URL 的 SHA-256 派生，防止两个目录的相同影片 ID 互相污染；原离线收藏键保持不变。
- 不会自动发现影视站、执行 `spider`、绕过 DRM 或连接任何第三方源；这部分需要先解决 FongMi 许可与可重复构建依赖问题。

## 云端验收

1. 单元测试：配置 JSON 往返、URL 合法性、重复 ID/URL、10 个目录上限。
2. Android TV 仪表测试：老数据迁移、新增、已有目录复用、切换离线、10 个目录上限以及跨源收藏隔离。
3. 原有目录 HTTPS 校验/缓存/重定向/超时、M2.2 续播、M2.3 播放器及 D-pad UI 回归全部保持通过。
4. 真机需检查 TCL 遥控器在源列表横向移动、选中源切换及输入法关闭后的第一下 OK 是否准确响应。
