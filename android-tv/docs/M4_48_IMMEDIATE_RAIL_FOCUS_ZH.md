# HERRIN M4.48：去掉上下海报栏切换的不必要首帧等待

## 实测依据

M4.43 的同一型号 Android TV SwiftShader 模拟器中，普通演示首页:
- 左右 40/40 焦点正确，焦点回调 P95 49.54ms；
- 上下 32/32 焦点正确，焦点回调 P95 81.73ms。

M4.44 下载调度优化后的不同 CI 运行中:
- 左右 40/40 焦点正确，P95 17.28ms；
- 上下 32/32 焦点正确，P95 117.99ms；
- 合成帧 P95 从 208.24ms 到 188.95ms，但都是 SwiftShader 软件渲染，不能证明真机改善。

以上上下数据有明显波动；我们不能把全部问题归因于海报网络。源码中 `transferPosterFocus` 即使目标 LazyRow 卡片已经挂载且在相同横向位置，仍**先进行整页滚动，再强制等至少一帧，才请求焦点**。在软 GPU 上这一帧可能非常昂贵，导致视觉上“按下遥控器没马上选中”。

## 本轮代码

1. 目标卡片已经挂载、横向位置已对齐：**先请求并确认真实焦点**，后续再完成页面垂直滚动；减少不必要的 `withFrameNanos` 强制等待。
2. 目标未对齐：先完成两栏滚动及 `LazyRow.scrollToItem`，**当前帧立即尝试**请求焦点；若 Lazy 尚未挂载，最多等待三帧重试，不放弃原有 offscreen 安全路径。
3. 本版 Compose `FocusRequester.requestFocus()` 返回 `Unit`，不能把“调用未抛异常”作为成功。请求后同时比较 `focusId == target`（由真实 `Poster.onFocusChanged` 回调更新），只有对上才认定焦点确已移动。
4. 这两类操作都留在原有「最新按键取消旧任务」单一 Job 内，不恢复早先的全局布尔锁。动画参数保持不变，避免用缩短过渡时间掩盖逻辑等待。
5. 沿用真实 Android TV API 30 的 32 次上下、40 次左右、20 次快速反向按键及多类别焦点自动验收；M4.47 的单仓 60 影片专项回归同样继续执行。无额外联网来源或遥控器权限。

## 复测标准

- 当前 HEAD 的 Android Debug、JVM、Lint 和 Android TV Emulator 全部成功才算通过。若新焦点验证影响电视焦点分发，必须修复，不以降低测试覆盖为代价。
- 对比同规格模拟器的上下 P95（81.73/117.99ms）和左右 P95，但单次 GitHub Actions 存在 CPU/GPU 抖动，不能宣称任何毫秒变化完全来自本轮。
- 向上/向下焦点必须处于正确目标并保持左右列位置，页面垂直滚动完成后不回跳。播放、字幕、源配置、视频解码、导航和历史回归不能退化。
- 尚未在 TCL T7L Ultra 真机测试真实“按键到屏幕发光”时间，不能宣称与 Infuse/VidHub 完全等效。
