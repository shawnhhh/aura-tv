# HERRIN M4.17 — TCL 实机 Spider 崩溃反馈与自动探测限时

## 实机反馈

用户在 TCL T7L Ultra 输入 `http://www.饭太硬.net/tv` 后，紧凑设置页一直显示「读取中」。随后进入影视站点选择页，错误文字明确为「Spider 子进程异常退出；主界面仍可使用」。这说明配置至少已解析成站点列表，**不等于影片目录、海报或播放已成功**。受保护第三方 ARM/JNI 插件原因尚无可读崩溃堆栈，不能断言具体 JNI 故障点。

## 改动

1. 自动扫描采取**45 秒总时间预算**，每个 CMS 最多分配 6 秒；存在可执行 Spider 候选时，CMS 总分配不超过 12 秒，为 Spider 保留尝试机会。每个 Spider 分配最多 20 秒。单仓首次导入不再对每一个失效站点独立耗尽完整网络/插件超时；底层同步网络读取可能延长最终完成时刻，预算为尽力限制。
2. 一旦 Spider 子进程异常退出，停止当次自动扫描，不再连续启动可能共享同一受保护 JAR 的多个插件站点。主界面继续可用。
3. 紧凑设置页不再只有单薄的「读取中」：显示当前尝试的站点序号/名称，并在结束时明确标出「插件崩溃」「检索超时」或「未获取到影片」。新增简短说明指向「选择影视点」以手动更换站点。
4. 用户手动点选其他站点的能力继续保留，不把普通 HTTP 404 或网络超时误判为进程崩溃。历史成功站点的 M4.16 优先排序与 Spider JAR MD5 授权校验保持不变。

## 验证范围

- JVM 单测：超时预算、CMS/Spider 时间分配、进程崩溃与普通错误区分。
- Android TV 模拟器：确保配置失败后在紧凑设置页面显示原因，原焦点/导航回归保留。
- CI 编译、Lint、APK 与模拟器结果以该提交 GitHub Actions 结果为准。
- 尚未确认受保护饭太硬 Spider 可以成功列出影片、显示真实海报或播放视频；下一步需在用户许可的 TCL 设备上获取崩溃原因，不可把本次状态修复误称为已修复第三方 JNI 崩溃。
