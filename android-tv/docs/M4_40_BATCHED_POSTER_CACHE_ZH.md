# HERRIN M4.40 — 海报缓存分批整理，减少首页密集下载时的磁盘竞争

## 起点与问题
继承已经通过 Android Debug / Android TV Emulator CI 的 M4.39 Draft PR #46，继续优化 TCL T7L Ultra 上的海报墙跟手感。上轮已有 8–32MB 解码位图 LRU、最多四路图片下载、卡片图片降采样、焦点即时反馈，但冷启动/新仓库的每张海报首次下载都在 `AuthorizedPosterCache.load` 中执行 `listFiles().sortedBy(...)` 及全目录统计，甚至未超过磁盘限额时也会重复扫描。

## 实际改动
- 新增 `PosterDiskCacheMaintenance`：每个缓存目录首次写入后清理一次，之后每 **16** 张成功写入再清理一次。普通图片下载不再重复枚举、排序和汇总全部缓存文件。
- 保持以 `.img` 为唯一清理对象，最多 **150** 个图片文件与约 **100 MB** 持久化空间；因为分批整理，两个阈值允许短暂超出，后续批次会恢复。避免无关应用数据被扫描或删除。
- 清理时按修改时间及文件名稳定排序、从最旧开始仅删除到满足限额，不再超过限额就直接删 25 张；本次刚下载的文件始终受到保护，避免电视文件系统粗粒度时间戳误删。
- 磁盘写入完成后才触发整理；图片 URL、来源权限、HTTP 同意、解码尺寸及缓存 LRU 均不变。仅调整本应用授权海报目录的本地磁盘管理。
- 提交四个 JVM 回归场景：16 张批次周期、最旧图片清理及其他数据隔离、按字节总额清理、同时间戳保护新图。

## 验收
- 执行本 PR HEAD 的完整 Android Debug（JVM + Android Lint + APK）和 Android TV Emulator 全量 instrumentation；不能使用 M4.39 上一轮成功冒充当前结果。
- 运行已有 M4.38 单仓 12 站点/60 影片性能场景，并在 CI 确认海报、播放、遥控等场景无回归。
- 本轮减少后台磁盘操作，并不直接证明 Android UI 帧 P95 已经改善；如需量化，须对相同模拟器配置和真实 TCL 录制前后帧时数据。
