# M4.28 应用内本地代理技术与验收报告

基线：`e1e8d6f44586cc2d8a7af5f1fc1b9777f0eaa0a2`。
分支：`feat/herrin-m4-28-loopback-proxy-20261029`。

## 已实现

- `MediaProxyPolicy.authorize` 要求调用方在用户明确授权后提交单一 HTTP/HTTPS 播放地址及请求头。没有通配域名、任意 URL 参数或开放代理入口。
- `MediaLoopbackProxy.start` 在电视应用内部启动 `127.0.0.1` 随机端口 ServerSocket，每会话使用 SecureRandom 生成 192 bit URL 令牌，每资源再生成独立随机 ID；其他设备不能访问监听器。
- 只有授权根地址和经整份 HLS 验证后发现的同源子资源可获取本地路由。浏览器 Origin、错误 Host、其他方法、请求体、多 Range 和伪造资源 ID 被拒绝。
- 支持 GET、HEAD、单区间及后缀 HTTP Range。向客户端保留 Content-Range、Accept-Ranges 和 Retry-After。上游 401/403/404/429/5xx 状态保留，错误正文和 Set-Cookie 不下传。
- 支持 HLS 相对分段、变体清单、EXT-X-MAP/EXT-X-MEDIA 等标准 `URI="..."` 属性；使用重定向后的清单地址作为相对解析基准。无扩展名 HLS 可由 `#EXTM3U` 内容识别。
- 严格相同 scheme/host/port；跨源跳转、跨源分段以及 HTTPS 降级都拒绝。同源重定向最多三跳，禁用 OkHttp 自动跳转、自动 Cookie 持久化和隐式连接重试。
- DNS 在实际建立连接的解析路径检查所有结果，再把已验证 InetAddress 列表直接提供连接层；私网、回环、链路本地、组播、保留、指向私网的映射及过渡地址等被拒绝。数值 IP 额外在策略层检查，覆盖 OkHttp 对 IP 字面量跳过 DNS 回调的情况。
- 用户授权 Cookie/Authorization 只在同源会话中传递；客户端任意 Cookie/Authorization/Forwarded 等头不转发，不记录完整 URL、令牌、Cookie、上游错误详情。
- 每会话最多四个工作线程、八个排队连接、16 KiB 请求头、64 个头字段、1 MiB 清单、每清单 2048 引用及会话 2048 唯一资源。请求头读取超时 10 秒，上游连接 10 秒、读取 15 秒。
- `close()` 幂等关闭监听器、活动/排队 socket、上游请求、连接池和执行器，并清空路由；有界等待 accept 线程退出，覆盖 JVM 原生监听 fd 延后关闭的情况。调用方后续接线必须在播放结束、切站或拥有者停止时关闭。

## 安全边界与首期限制

本模块第一阶段保持独立，未接入播放器 UI、未改变 Apple TV 风格，也不触碰剧集/线路/播放 ID、Cookie 会话实现或 Dolby/HDR 检测。

只有调用方确实取得用户授权时才可调用 `authorize`，该函数不会生成或证明内容授权。局域网来源不在首期允许范围。跨 CDN 同源外资源暂不支持，后续必须单独获得用户授权并继续限制凭据传播。

加密 HLS（包括 AES-128、SAMPLE-AES、会话密钥）、DASH 清单、HLS 变量与 Content Steering 首期明确拒绝，不获取密钥、不实现 DRM 解密或权限绕过。普通 MP4/分段字节可流式转发；DASH 的原生直连播放器路径不受本模块影响。

资源上限也会限制很长的直播会话；未来需要经测试的窗口淘汰方案。暂未进行真实电视局域网端口探测、长期带宽/内存测试或独立渗透审计，因此总集成不得自动接入播放器。
