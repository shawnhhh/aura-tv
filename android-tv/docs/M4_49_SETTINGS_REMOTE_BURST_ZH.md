# HERRIN M4.49 — 解决设置页快速连按的按键意图丢失

## 自测发现的交互问题

在 M4.48 代码检查中，内容来源设置页的 LazyColumn 用 `onPreviewKeyEvent` 截获上下方向键，每次均根据 `focusId`（**已实际完成聚焦的旧控件**）计算下一个目标。而 `moveCompactSettingsFocus` 在目标离屏时会先 `scrollToItem`，再等待布局/焦点回调。用户快速按下四次 Down，若第一个焦点回调没赶上后续输入，可能连续四次都被解析成同一个下一行——按键合法但没有前进。

同页此前还把 `FocusRequester.requestFocus()` 的 **无异常返回**当作已成功聚焦。本版 Compose 返回的是 `Unit`，即使目标实际未获得焦点，也可能直接退出恢复流程。和影视首页的 M4.48 修复相比，这是遗漏的设置页路径。

## 实际代码修复

- 新增无响应式 Compose 状态的纯 Kotlin `CompactSettingsIntent`。每个 KeyDown 基于上一条**目标焦点意图**（而不只是最后实际聚焦）计算下一行；上下反向也逐键更新，第一行/最后一行仍不绕回。
- 通过 `moveCompactSettingsFocus` 取消旧协程并沿用最后一个目标。目标已挂载即同帧请求，否则 scrollToItem 后立即尝试、未挂载则最多再试三帧。
- 以现有焦点回调更新的 `focusId == target` 核验请求真实完成，而不是只判断不抛异常。已到达最新目标则清理意图；旧目标迟到回调不清空更新后的意图；目标三帧未到达则清理对应失效意图。
- 页面退出或从紧凑设置转入高级设置时，取消未完成任务并清空意图，不让旧焦点污染下一次进入。
- 现有“影视源”“直播源”输入入口仍维持**遥控器 OK 才打开输入编辑器**；上下键只移动到导航按钮，不主动弹出键盘。
