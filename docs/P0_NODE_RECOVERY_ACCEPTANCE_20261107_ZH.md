## 证据与根因边界

### 影视节点提示插件崩溃

目前没有 TCL 的 logcat、该次崩溃堆栈、用户的配置文件或授权 JAR。环境没有这些秘密或设备连接，因此不能断言饭太硬的具体异常，更不能宣称其真实节点已修复。

代码复核确认：子进程断开均返回“Spider 子进程异常退出”；导入入口把该消息一律显示为“插件崩溃”。但搜索取消与宿主超时也会主动回收同一子进程，原提示不能区分宿主超时和插件崩溃。另外，Worker 仅记录异常类名，缺少定位帧。

修改：保存有限的 Java 异常原因链和 class/method/line；记录初始化、搜索等阶段；未捕获异常先保留脱敏结构，再交回 Android 原有异常处理器。超时回收留有 WATCHDOG 阶段；导入提示按已有阶段与 OS 退出分类区分“插件响应超时”“插件进程退出”和已记录崩溃。故障不改变其他节点的执行权限。

不保存 Throwable.message、请求体、Cookie、Token、媒体 URL、本机文件路径或 native tombstone；保留至多四层原因链，每层十二帧。安全诊断文件：应用私有目录 `spider-failure-structure.txt`，只展示最近两分钟的记录。未授权的 Spider、变更后的 JAR 或配置仍不能自动执行。

### 搜源停在 1/44 与继续无效

已确认的代码问题：授权批次的终态事件没有 `nodeComplete=true`，因此 `SourceSearchPlans` 无法把批次终态写入已检查集合；仅靠界面游标不能防止回到前面的节点。另有激活与普通搜索共用 1200ms 阶段预算的路径，冷启动超过此预算即被回收，不能据此断言源无影片。

修改：
- 每个真实完成/失败/超时节点发布一次终态，按不变配置计划中的 source ID 去重；继续扫描以已完成集合跳过旧节点，即使 UI 游标归零也不重复执行。
- 总数使用当前有执行权限的 CMS/Spider 和已配置个人源，不把未授权格式加入计划；临时冷却节点保留为剩余，不能伪造已检查数。
- 独立激活预算 3000ms；普通阶段 1200ms；媒体阶段 2800ms；批次单节点上限 6000ms；总前台 8000ms/主动继续 15000ms 保留。批次使用实际剩余总预算，并预留 150ms 返回结果。
- 保持个人源 → 首选影视点 → 其他影视点。更换首选仍立即取消旧任务并清除旧路由。
- “查找其他影视点”保留已发现的选集与来源身份，不提前删除；会话失效仍必须刷新授权与媒体，不能把旧代理 URL 当成可播放。
- 继续/重新检索入口直接根据计划剩余身份判断，不再依赖提示文案或 UI 游标；前后台恢复保留同一配置计划，仅显式重新检索或配置身份变化时重置。
- 进度按 source ID 汇总已检查、真实媒体验证成功、失败、超时和剩余；搜索匹配或初始化成功不算播放成功。

回归覆盖冷激活预算、终态唯一性、游标归零后继续不重复、失败节点不阻断后续节点以及计数去重。这些是确定性调度复现，不能证明 TCL 的唯一根因，也不代表真实源的响应速度。

### 影片没有播放

没有真实授权影视源时，不能认定 CMS、Spider 或代理在 TCL 的具体失效环节。保留现有 FongMi/TV、ParseJob、Proxy、Media3 核心。

本轮发现并复现的媒体接入问题：HTTP read 可能仅返回一个字节，旧验证器立即用首包判断 `#EXTM3U`，把分片返回的真实 HLS 清单误判为无效。修复为在既有可取消请求、超时和范围约束下最多收集 1 KiB，再判断清单；不下载整片，不放宽本地代理权限、TLS 或媒体错误页校验。

新增 JVM 分片 HTTP 清单回归；新增 TV 回归通过生产媒体验证器后使用真实 TLS 原创 HLS/TS，由现有播放器渲染视频帧，并保留字幕、暂停、拖动、Back 释放断言。现有 CMS HTTP、JSON 解析、WebView 嗅探、MP4/HLS/DASH、DEX Spider、签名源到 Proxy 和音视频解码测试全部保留。

### 唯一失败的 Compose 测试

基线真实日志：工作流 https://github.com/shawnhhh/aura-tv/actions/runs/42378286540 ，231 项中 1 项失败。`HerrinUiSmokeTest.onlineSearchProtocolEmptyAndRemoteResult` 在第 686 行等待返回搜索卡片焦点超时 5000ms；该测试此前已通过查询、结果与详情资料/无授权选集的断言。

原因路径：返回搜索触发异步结果重建，卡片暂未挂载；中间焦点事件会覆盖共享 focusId，原卡片挂载时依赖该共享值恢复，目标丢失。修改为进入详情前单独保存搜索卡片身份，Back 发出恢复请求；结果挂载后按保存身份恢复，恢复成功才清除请求。没有延长测试等待、删除失败断言或跳过测试。

中间版本 `939a0cc` 的模拟器实测已通过原第 686 行卡片恢复断言和新增分片 HLS 实际出帧，但随后在同一测试的第 692 行返回工具栏断言失败，另一项高级筛选测试也失败。日志显示部分确认键停在 IME、未交给 Activity；生产 IME 交接只覆盖卡片，遗漏搜索筛选按钮。`26b58dd` 把交接扩展至搜索非输入按钮，测试保持所有断言并增加输入连接已释放的前提；第二次输入查询后先聚焦结果卡，再验证 Back 返回工具栏，避免将编辑器的“关闭键盘”当作离开页面。

## TCL 与实际授权源必须补验

1. 安装本轮最终 APK，获取故障时的 logcat 与脱敏异常结构（debug APK 可用 `adb shell run-as tv.herrin.app cat files/spider-failure-structure.txt`）；区分宿主 WATCHDOG、JNI/ABI、Java 初始化、网络和授权错误。
2. 使用用户已授权的原始仓与 JAR 身份；打开首选节点，失败后确认其他节点可继续，核对失败和超时计数。
3. 前台超时后继续扫描，确认已检查节点不再执行，未完成节点可恢复，已有选集仍可见。
4. 实际选集 → playerContent → ParseJob/Proxy → Media3：验证视频帧、音频、拖动、续播、重试、换线路与返回选集。原生组件、HDR/Dolby、长片和运营商网络均需 TCL 测量。
5. 不把原创本地测试片、在线 TMDB 元数据或返回 URL 当成真实第三方播放成功；不绕过授权、DRM 或用户凭据安全规则。

中间版本 `26b58dd` 的 TV 实测 232 项中 1 项失败：搜索测试在第 679 行详情尚未打开。按键日志在 `IME handoff` 后仅记录 `TEST inject code=23`，没有对应的 Activity dispatch；筛选回归已通过。`66aaf76` 仅补齐测试的系统输入路由就绪前提，产品源码与 `26b58dd` 字节一致。

后续完整 TV `66aaf76`：原在线搜索回归通过，新增分片 HLS 出帧通过；高级筛选和单仓目录等待两项失败（232 项共 2 失败）。高级筛选的真实按键仍未进入 Activity，证明窗口可见性/输入连接布尔值及测试空闲检查不足以结束原生 served-view 状态。`904b465` 补充释放原生搜索 served view 并恢复同一 Compose 目标；单仓测试保留原等待/海报/性能断言，在失败时额外输出 fixture 请求数与语义树，未对未知目录故障作猜测性补丁。最终状态以该版本之后的全套结果为准。
